# Legible Studio — Rust Port Roadmap (June 3, 2026)

**Scope:** New construction only (no renovations — Part 11 is a later phase).  
**Workflow:** LiDAR as-built capture → generate drawings → export PDF/DWG/IFC for engineers.

### Phase 3 — "LiDAR As-Built to Plans" (6–10 weeks)

**Goal:** Walk a site with LiDAR, capture existing conditions, generate as-built drawings, then overlay new design.

**Phase 3 is complete (3.1–3.5 all ✅).** `crates/site/src/footprint.rs` does height-threshold + convex-hull segmentation from DEM rasters; `crates/site/src/aswall.rs` detects interior walls from a point cloud; `crates/site/src/aselevation.rs` projects exterior clouds to per-facade outlines + openings; the floor-plan slicer renders existing walls/doors/windows as dashed-grey overlay linework against solid-black new design; and a `existing` renovation flag on walls/doors/windows backs the existing-vs-new data model.

| # | Task | Why | Effort |
|---|---|---|---|
| 3.1 | ✅ | **Building footprint from LiDAR** — `site::extract_footprint` takes a WGS84 bbox + DSM tile index (+ optional DTM) and samples a grid. Points where `DSM - DTM > threshold` (or `DSM - min(DSM)` when DTM is absent) are kept; the 2-D convex hull of those points is returned as `polygon_mm` in local plan coordinates. `legible-footprint` CLI reads `site.json`, scans `--dsm <dir>` (and optional `--dtm <dir>`), and writes a `footprint.json` compatible with `qbd_dump --footprint`. Integration tests use synthetic Ontario DEM tiles with a centred elevated block and verify the hull area and ground elevation. | As-built capture starts here. | Medium |
| 3.2 | ✅ | **As-built floor plan** — `site::detect_walls` reduces vertical-plane segmentation to 2-D line detection: slice a horizontal band above the floor, project to plan, voxel-downsample, then iteratively extract the strongest line via a deterministic Hough vote (θ, ρ), refit it to its inliers (PCA), split it at scan gaps (doorways → separate segments), and keep runs over a minimum length. Returns `AsBuiltWall` centrelines in plan mm + floor/ceiling elevation. `legible-aswall` CLI reads an ASCII XYZ cloud and writes `SchemaWall`-shaped JSON with `category: "as_built"`. Tests cover a 4-wall room, doorway-gap splitting, band filtering out floor/ceiling clutter, and empty-band/empty-cloud errors. | Existing walls for renovation context. | Large |
| 3.3 | ✅ | **As-built elevation** — `site::project_all_elevations` slices the cloud per cardinal facade (points within `facade_depth` of each face), projects them onto the facade plane (h along the wall, v up from the ground datum), bins an occupancy grid, and finds **openings** as connected empty cells sitting below their column's roofline — doors reach the ground, windows float. Returns a bounding-rect outline + classified opening rectangles per facade. `legible-elevation` CLI reads an XYZ cloud and writes `elevations.json` (one entry per facade). Tests cover a blank wall, a window+door wall, all four facades of a box, and an east-facade window (z-as-horizontal). Shared `cloud::parse_xyz` now backs both as-built CLIs. | Existing facade for designers. | Medium |
| 3.4 | ✅ | **Design overlay** — `ParametricWall` now carries the schema `category` (backward-compatible serde, not emitted when empty); `slice_wall` styles `category == "as_built"` walls as **dashed, mid-grey, unhatched** reference linework while new-design walls keep the solid-black hatched style. `svg_polyline` learned to honour dashed/hidden line types (it previously dropped them — only `svg_line` did). A mixed floor plan now reads existing-vs-new at a glance. Tested at the slicer level (as-built dashed/grey/unhatched + new-design regression), the SVG level (polyline dasharray), and end-to-end through `generate_floor_plan_with_openings`. | "Before/after" is the value prop. | Small |
| 3.5 | ✅ | **Renovation flag** — `SchemaWall`/`SchemaDoor`/`SchemaWindow` carry an `existing: bool` (serde default `false`) with `is_existing()` helpers; the wall helper also honours the legacy `category == "as_built"`. The flag is carried onto `ParametricWall` and drives the overlay styling so existing doors (grey dashed leaf + arc) and windows (grey dashed glazing) match the existing-wall linework. `legible-aswall` now emits `existing: true`. Part 11 compliance stays deferred, but the data model cleanly separates construction type (`category`) from lifecycle (`existing`). | Sets up future Part 11 work. | Small |

**Acceptance:** LiDAR scan → `legible-stitch` → building outline detected → floor plan shows existing walls dashed, new walls solid. ✅ Met: `legible-footprint`/`legible-aswall`/`legible-elevation` capture as-built geometry, and the floor-plan overlay renders existing-vs-new for walls, doors, and windows.

## 6. Immediate Next Step

**Phases 1, 2, and 3 are all complete.** The permit-set bundle ships 16 PDF sheets + floor-plan/elevation DXF; IFC carries walls, openings, slabs, and strip footings; the API returns SVG, IFC, DXF, and compliance summary on demand. The as-built stack spans capture-to-overlay: `legible-footprint` extracts building outlines from Ontario LiDAR DEMs, `legible-aswall` detects interior walls and emits as-built `SchemaWall`s, `legible-elevation` projects exterior clouds to per-facade outlines + classified window/door openings, the floor-plan slicer renders existing walls/doors/windows as dashed-grey overlay against solid-black new design, and the `existing` renovation flag separates lifecycle from construction type across the schema.

### Stairs (OBC 9.8) — ✅ shipped as a rules-engine category

Stairs are now a first-class annotation alongside detectors/electrical/headers, end-to-end:
`obc::stairs` solves the rise/run for a storey height (fewest equal risers ≤ 200 mm, treads at the 255 mm minimum going) and checks rise/run/clear-width/handrail/headroom; the solver emits a `SchemaStair` per storey shaft, choosing a **straight** run when it fits the bay and a **U-switchback** (two flights + central well + back-wall landing) when it doesn't; `drawing::render_stair_symbol` draws the tread nosings, central well, landing, and an `UP`/`DN` direction arrow into the floor plan; and the compliance report carries one row group per stair (OBC 9.8.2.1 / 9.8.4.2 / 9.8.7.1 / 9.8.2.2). The default 2-storey house folds 16 risers into a switchback whose flights clear 860 mm; single-storey houses emit none. Verified across a 75-combination bed/bath/sqft sweep.

**Stair section sheet — ✅ shipped.** `drawing::stair_section` draws a typical stair section (sheet A-502): the riser/tread sawtooth between the two finished floors, the stringer, a handrail, and the stairwell opening with the **1950 mm headroom** dimensioned at the binding nosing (OBC 9.8.2.2), plus floor-to-floor, total-run, and a rise/run step callout, with an OBC notes block (9.8.4.2 / 9.8.2.2 / 9.8.7). Generated from the solved `SchemaStair` when the building has stairs (none on a single storey), title-blocked into the bundle and the combined PDF/PNG (now 17 pages on the default 2-storey house).

**`IfcStair` in the IFC export — ✅ shipped.** `qbd::ifc` emits one `IfcStair` per physical run (the "up" stair on each storey; the matching "down" copy on the floor above is skipped to avoid doubling), aggregating an `IfcStairFlight` that carries the riser/tread semantics (`NumberOfRisers`/`NumberOfTreads`/`RiserHeight`/`TreadLength`) with a bay-box solid spanning floor-to-floor. The turn is the `IfcStair` predefined type — `.STRAIGHT_RUN_STAIR.` or `.HALF_TURN_STAIR.` for a switchback. The stair is spatially contained in its storey and its flight is aggregated under it, so Revit imports it as a proper stair.

Remaining stair follow-ups (v2): a true two-flight switchback in both the section sheet and the IFC (separate flights + a landing slab) rather than the representative single-flight model.

### In-house SVG→PNG raster — ✅ shipped

Plan previews no longer need an external rasteriser (Inkscape). `qbd::raster` (`Rasterizer` / `svg_to_png`) renders any sheet SVG to PNG with **resvg + tiny-skia** — the same pure-Rust crates the desktop head and the `svg2pdf` PDF path already build, with system fonts loaded so the text-heavy sheets render correctly. Exposed as `qbd_dump --png <dir> [--png-width <px>]`, sharing the sheet set + order with `--pdf-combined`. The pipeline now emits SVG + PDF + DXF + **PNG** entirely in-house.
