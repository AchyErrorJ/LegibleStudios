# Legible Studio — Rust Port Roadmap (May 31, 2026)

**Target:** Code-compliant Part 9 low-rise residential permit sets in one sitting.  
**Scope:** New construction only (no renovations — Part 11 is a later phase).  
**Workflow:** LiDAR as-built capture → generate drawings → export PDF/DWG/IFC for engineers.

## 2. The Roadmap: Three Phases

### Phase 1 — "Permit-Ready PDF" (4–6 weeks)

**Goal:** Press one button, get a PDF bundle you can submit to a building department for a simple house.

| # | Task | Why | Effort |
|---|---|---|---|
| 1.1 | **PDF export** — Convert SVG sheets to PDF (via `printpdf` or `svg2pdf`). One PDF per sheet, plus a combined PDF with sheet index. | Permit submissions are PDF. Engineers review PDF. | Small |
| 1.2 | **Foundation plan** — Footing outline under exterior walls, slab edge, step footing for grade changes. Render as a new drawing sheet (`03_foundation_plan.svg`). | Required for every Part 9 permit. | Medium |
| 1.3 | **Code compliance report sheet** — Take `ValidationResult` from `qbd::validate_layout` and render it as a tabular sheet: wall-by-wall pass/fail, thermal R-value check, header sizing, joist spans. | Building departments and engineers need to see compliance demonstrated. | Small |
| 1.4 | **Framing plan (v1)** — Joist direction and spacing from OBC span tables, beam locations at long spans. Simple lines + annotations, not full structural engineering. | Framers and engineers need this. OBC tables already loaded. | Medium |
| 1.5 | **Foundation detail** — One typical footing detail (width, depth, rebar) for the default soil condition. | Required detail sheet. | Small |
| 1.6 | **Smoke-test as PDF bundle** — `python smoke_test.py --pdf` produces the full PDF set. | Demo and regression. | Small |

**Acceptance:** Run smoke test → open PDFs → floor plan has detectors, foundation plan exists, compliance report lists all checks as pass.

---

### Phase 2 — "Engineer Handoff" (4–6 weeks)

**Goal:** Export DWG + IFC that engineers can open in AutoCAD/Revit and spec out.

| # | Task | Why | Effort |
|---|---|---|---|
| 2.1 | **DWG export** — Use `dxf-rs` (or emit DXF and let AutoCAD open it) for geometry + annotations. Start with floor plan + elevations. | Engineers live in DWG. | Medium |
| 2.2 | **Complete IFC** — Add `IfcOpeningElement` + `IfcRelVoidsElement` so doors/windows properly void walls in Revit. Add `IfcSlab` for floors, `IfcFooting` for foundation. | Revit import needs proper voiding. | Small |
| 2.3 | **API server** — Wire `axum` routes: `POST /solve` (answers → building JSON), `POST /draw` (building JSON → SVG/PDF/DWG/IFC), `GET /health`. | Headless integration, future web UI, engineer portal. | Medium |
| 2.4 | **Title block v2** — Project name, address, designer license number, drawing scale, date, sheet index. Ontario-specific notes (OBC 9.10.19 smoke alarm note, 9.33.4 CO note). | Permit drawings need proper title blocks. | Small |
| 2.5 | **Structural grid + dimensions on all sheets** — Elevations and sections get level dims, section markers reference floor plans. | Professional drawings need cross-referencing. | Small |

**Acceptance:** Open DWG in AutoCAD — walls, doors, dimensions visible. Open IFC in Revit — walls have openings, spaces have areas.

---

### Phase 3 — "LiDAR As-Built to Plans" (6–10 weeks)

**Goal:** Walk a site with LiDAR, capture existing conditions, generate as-built drawings, then overlay new design.

| # | Task | Why | Effort |
|---|---|---|---|
| 3.1 | **Building footprint from LiDAR** — Segment building outline from terrain point cloud (simple height-threshold + convex hull, not full ML). | As-built capture starts here. | Medium |
| 3.2 | **As-built floor plan** — Detect walls from interior point cloud (vertical plane segmentation). Emit as `SchemaWall` with "as_built" category. | Existing walls for renovation context. | Large |
| 3.3 | **As-built elevation** — Project exterior point cloud to elevation planes. | Existing facade for designers. | Medium |
| 3.4 | **Design overlay** — Render as-built walls as dashed grey lines, new design as solid black lines, on the same floor plan. | "Before/after" is the value prop. | Small |
| 3.5 | **Renovation flag** — Mark new vs existing walls, doors, windows in the schema. Part 11 compliance deferred, but the data model supports it. | Sets up future Part 11 work. | Small |

**Acceptance:** LiDAR scan → `legible-stitch` → building outline detected → floor plan shows existing walls dashed, new walls solid.

## 3. What's NOT on This Roadmap (and why)

| Item | Why deferred |
|---|---|
| **Part 11 (renovations)** | Different code sections, different drawings (existing vs new). Do after Part 9 is solid. |
| **Plumbing/HVAC plans** | Part 9 doesn't require them for permit submission in Ontario. Nice-to-have, not blocking. |
| **3D render / Vulkan** | Separate product line (LegiView). Permit drawings are 2D. |
| **Full structural engineering** (hold-downs, shear walls, engineered trusses) | Requires engineer stamp anyway. We pre-mark assumptions; engineer verifies. |
| **AI render hero shots** | Marketing tool, not permit-critical. |
| **Mobile app** | Desktop-first for permit generation. Mobile comes after workflow is proven. |

## 6. Immediate Next Step

**Phase 1.1: PDF export.** It's the smallest task with the biggest demo impact. A PDF bundle is what building departments and engineers actually handle. Everything else (foundation plan, compliance report) feeds into the same bundle.

Suggested crate: `printpdf` (MIT, pure Rust, SVG-like API) or shell out to `inkscape --export-filename` if a binary dependency is acceptable.
